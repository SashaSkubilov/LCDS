# Использование формата JSON для локального хранения данных

## Контекст и постановка задачи
Приложению FitLog требуется хранить историю тренировок. По требованиям (SRS) приложение не должно использовать внешние базы данных и облачные сервисы. Какой формат хранения выбрать?

## Драйверы решения
* Простота реализации и развертывания.
* Отсутствие необходимости установки дополнительного ПО (СУБД).
* Возможность легкого резервного копирования (файл можно просто скопировать).

## Рассмотренные варианты
* JSON-файлы.
* SQLite (встроенная БД).

## Итог решения
Выбран вариант «JSON-файлы», потому что он полностью удовлетворяет требованию локальности, не требует подключения JDBC-драйверов и библиотек SQL, а для объемов данных одного пользователя его производительности достаточно.

### Последствия
* **Хорошо, потому что**: Легко реализовать, можно открыть и прочитать файл блокнотом.
* **Плохо, потому что**: При очень большом количестве тренировок (тысячи записей) может замедлиться чтение/запись всего файла.

### Подтверждение
Проверка осуществляется через тестирование сохранения и загрузки данных при закрытии и открытии приложения.

## Плюсы и минусы вариантов
### JSON-файлы
* Хорошо, потому что просто и без зависимостей.
* Плохо, потому что нет ACID-транзакций.

### SQLite
* Хорошо, потому что быстрый поиск и надежность.
* Плохо, потому что нужно подключать стороннюю библиотеку и писать SQL-запросы.
