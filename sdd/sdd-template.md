## 1. Введение
### 1.1 Назначение документа
Данный документ описывает архитектурный дизайн и системные требования для десктопного приложения FitLog. Документ предназначен для команды разработчиков и архитекторов.

### 1.2 Область применения
Проектируемая система — приложение FitLog (версия 1.0). Входит: работа с локальными данными (JSON), интерфейс на JavaFX. Не входит: облачная синхронизация, мобильная версия.

### 1.3 Определения, акронимы и сокращения

|------|------------|
| MVC | Model-View-Controller — паттерн проектирования |
| JSON | JavaScript Object Notation — формат хранения данных |

## 2. Обзор дизайна
### 2.1 Задачи стейкхолдеров
- **Пользователи**: удобный интерфейс для быстрого ввода данных.
- **Разработчики**: чистая архитектура (MVC) для легкого сопровождения.

### 2.2 Выбранные точки зрения
#### 2.2.1 Контекст
Система FitLog является локальным десктопным приложением. Внешние системы не используются. Актор — Пользователь (атлет/новичок).

#### 2.2.2 Композиция
Приложение разделено на три модуля:
1. `UI Module` (JavaFX, FXML).
2. `Domain Module` (классы Exercise, Workout).
3. `Data Module` (работа с JSON-файлами).

#### 2.2.3 Логическое представление
Используется паттерн MVC. Основные классы: `MainApp` (запуск), `WorkoutController` (логика), `WorkoutModel` (данные).

#### 2.2.7 Информация
Данные хранятся в файлах `workouts.json` и `exercises.json`. Структура JSON соответствует классам модели.

## 3. Проектные представления
- **ID**: 001-Architecture
- **Title**: Общая архитектура FitLog
- **Viewpoint**: Composition
- **Representation**: Клиент-серверная архитектура отсутствует. Используется монолитное десктопное приложение с четким разделением слоев (MVC). Слой View (JavaFX) взаимодействует с Controller, который обновляет Model и сохраняет данные в JSON.
- **More Information**: Реализует требования REQ-FUNC-001 и REQ-FUNC-002 из SRS.

(Ссылка на ADR)
